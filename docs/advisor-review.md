# 网页端顾问定向审查｜2026-09-15

会话：[审查分店扩张痛点](https://chatgpt.com/c/6aa94cd0-8878-83eb-ba98-9ee9bcfc508e)。本轮发送 1 个完整审查提示，以及在用户新增“备菜/炒菜照片、最小场景”后 1 个定向复核提示，共 2 个；复用已登录的既有对话。对方是咨询者，不替代 Codex 的事实核对、实现或验收。

采纳的产品问题与最小修改：

1. 员工不应被迫一进页就触发 RAG → 当前 B1 批准卡放在提问前，短提醒可展开全文。
2. A0 无本店资料 vs A2 检索版是知识和检索两变量 → 加 A1 批准卡全文入模状态；UI 和 PRD 都明示 A0→A2 不支持检索净收益，且三道短卡不足证明 RAG 比全文优。
3. 已明确含花生不能一概升级 → 按批准事实直接回答“不适合花生过敏者”；未记录的其他过敏原/食品安全关口转主厨。
4. 资料图与菜品图不能混同 → 文字 SVG 资料图对应预置 OCR 草稿，备菜/炒菜/成品图仅人工参照；本机图/音都只手工填改。
5. 上传页操作密集、问答手机双栏不自然 → 主厨页按选菜/采集/草稿审核逐层展开；员工页一次一条短答，对照藏在显式实验切换器下。
6. 第二部手机必须有触发门槛 → 员工点「问主厨」先看求助摘要，再确认「发送模拟求助」；右下角才出现小主厨手机并标非真实推送。上传页从不显示它。
7. 用户新增照片判断 → 顾问确认只需番茄炒蛋一组过程图，不必为三菜补图库；过程/成品图标成人工参照，文字资料图才对应预置 OCR，炒蛋状态写成主厨批准说明，不写成视觉识别结果。一个初见者能准确解释这个边界，即停止继续加图。

没有采纳“做十题测试”作为当前上线前硬门槛：本 Demo 只有三道菜与各 3 个代表问句；本轮用 9 个固定问题覆盖步骤、过敏原已知/未知、经验线索、未批准，另在后续真实试点扩题。顾问提出的 OCR/ASR 节省时间、语音高峰可用、RAG 比搜索快、减少主厨中断等均是待现场验证，Demo 不写成结果。
